- Catalogue feeds: logic in `catalog.ts` (tested); `importFeed` adds AI mapping + live shop fetch (key from env var named by `credentials_secret_ref`) and writes only via `supplier_import_products`; confirmed categories survive re-imports.
- Notification emails: SQL only writes `notifications`; `notify-email.server.ts` (rules in tested `notify-email.ts`) emails new rows every 2 min via `/api/public/notifications/dispatch` and the admin button, tracking `email_status`; demo companies are never emailed.
- Company data: VAT checks call EU VIES live from `company-data.functions.ts` (parsing in tested `vies.ts`), saved to `company_public_data` then `compute_trust_score`; register/Sodra/VMI imports remain seeded.
- Go-live: checklist/test data in tested `go-live.ts`; admin `/admin/go-live` reads `integrations` + server readiness, ticks kept in localStorage.
- Material Lens: `identifyMaterial` reads private, EXIF-stripped photos and validates every photo index via `parseLensProducts`; same-product views share an item, distinct products stay separate in scan JSON, and incomplete multi-photo responses fail without sample substitution. `lensProducts` reads legacy scans; Request offers transfers all drafts into one RFQ for quantity entry and explicit confirmation. Supplier choices use `lens_suppliers` and `preferred_supplier_ids`.
- Magic-link Material Lens uses `identifyMaterialByToken` (token checked via `magic_get`, photos sent inline, nothing stored); chat camera only fills the user's own message box, never posts as AI.
- Scan photos follow the RFQ: `rfq_scan_photos` RPC + `can_read_scan_photo` storage policy let the buyer and invited suppliers see the scan photo (shown by `ScanPhotos`), without copying files.
- Payment deadline: `orders.payment_due_at` set on insert from `platform_settings`; `expire_unpaid_orders` cancels via the 5-min tick.
